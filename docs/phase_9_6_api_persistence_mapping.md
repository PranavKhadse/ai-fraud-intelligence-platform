# Phase 9.6 — API Integration & Persistence Mapping Architecture

## Overview
This document defines the architectural integration boundary between the real-time Fraud Risk Scoring API (`/predict`, `RiskService`, `RiskEvaluator`) and the asynchronous persistence layer (`FraudPersistenceService`, `FraudPersistenceUnitOfWork`).

It specifies the exact field mappings, data transformations, default fallbacks, and gap classifications required to convert inference evaluation payloads into typed `PersistRiskEvaluationCommand` instances without introducing database coupling into the synchronous scoring engine.

---

## 1. Classification Categories

Every persistence field is classified into one of four categories:
1. **Available Now**: Present in current request or response schemas and requires no transformation.
2. **Requires Transformation**: Available in memory, but requires conversion (e.g., float to Decimal, string to Enum, string to datetime, extraction from nested structure).
3. **Not Currently Available**: Not generated by the current model/rule inference pass, requiring deterministic defaults or context resolution.
4. **Deferred to Later Increment**: Requires endpoint-level integration, middleware, or HTTP request context (e.g. live database session injection, FastAPI background task).

---

## 2. Hardening & Correctness Rules (Increment 1A)

During the Phase 9.6 Increment 1A audit, the following safety rules were enforced:

1. **No Invented Business Entities**:
   - `account_id`: The mapper **rejects** missing or empty `account_id` with a clear `ValueError`. It does not invent fake `"UNKNOWN_ACCOUNT"` strings. The account identifier must be provided either in the request payload or explicitly via `RiskEvaluationContext`.
   - `model_version`: The mapper **rejects** missing or empty `model_version` with `ValueError`, guaranteeing model provenance integrity.
   - `merchant_id`: Preserved as `None` if not provided in the request or context (never fabricated).
   - `external_transaction_id`: Preserved as `None` if omitted in the request or context (never fabricated).

2. **Numerical Finiteness & Bounds Validation**:
   - Rejects `NaN` or infinite values (`math.isinf`, `math.isnan`) across all numerical features, scores, coordinates, and attributions with `ValueError`.
   - Rejects negative `amount` (`< 0.0`) or negative `city_pop` (`< 0`).
   - Rejects coordinates outside valid geographic ranges (`cardholder_lat` / `merchant_lat` not in `[-90, 90]`, `cardholder_long` / `merchant_long` not in `[-180, 180]`).
   - Rejects `model_score` outside `[0.0, 1.0]` or integer `risk_score` outside `[0, 100]`.
   - Rejects relative contribution percentage outside `[0.0, 1.0]` or rank `< 1`.

3. **Strict Enum Validation**:
   - Rejects invalid enum strings with a descriptive `ValueError` listing allowed values for `PolicyMode`, `RiskTier`, `DecisionAction`, `RuleOutcome`, `RuleType`, `ReasonSource`, `ReasonSeverity`, `AttributionDirection`, and `AuditActorType`.

4. **Currency Validation**:
   - Validates that currency is a valid 3-letter ISO 4217 uppercase alphabetic string (e.g. `"USD"`).

5. **Complete 55-Predictor Feature Snapshot**:
   - Slices exactly the 55 canonical features defined in `PREDICTIVE_FEATURE_COLUMNS`.
   - Rejects incomplete feature vectors if any required predictive column is missing from the payload.
   - Excludes internal non-predictive metadata (such as `is_fraud` or internal database columns) from the snapshot.

## 5. Phase 9.6 Increment 2 Implementation Details

In Phase 9.6 Increment 2, the persistence layer was safely wired to the `/predict` and `/api/v1/predict` endpoints.

### A. Persistence Execution Strategy
- **Strategy**: **Inline Transactional Persistence**.
- **Justification**: Financial fraud risk scoring demands synchronous persistence guarantees before risk actions (APPROVE, REVIEW, BLOCK) are returned to downstream checkout flows and payment gateways. Inline persistence ensures:
  1. Duplicate transaction detection triggers **HTTP 409 Conflict** immediately.
  2. Database failures trigger **HTTP 500 Internal Server Error** with automatic rollback, preventing false-positive acknowledgments.
  3. All 6 aggregate entities (`Transaction`, `RiskEvaluation`, `RuleMatch`, `ReasonCode`, `FeatureAttribution`, `AuditLog`) commit atomically in a single transaction before HTTP 200 is issued.

### B. Dependency Injection Architecture
- `get_persistence_service(session: AsyncSession = Depends(get_db_session)) -> FraudPersistenceService` is provided as a standard FastAPI dependency in `backend/app/services/persistence_service.py`.
- Session lifecycle, rollbacks on unhandled errors, and connection disposal are managed by `get_db_session`.

### C. Request Lifecycle & Context Extraction
1. **Monotonic Latency**: Measured using `time.perf_counter()` strictly around the ML inference and TreeSHAP explainability pass (`eval_latency_ms`).
2. **Correlation ID**: Extracted from incoming HTTP request headers (`X-Correlation-ID` or `X-Request-ID`).
3. **Client IP & Anti-Spoofing Policy**:
   - Governed by `settings.TRUST_PROXY_HEADERS` (default: `False` for zero-trust security).
   - In untrusted mode (`False`): Strictly extracts direct connection IP from `request.client.host`, ignoring client-provided `X-Forwarded-For` or `X-Real-IP` to prevent IP spoofing in audit trails.
   - In trusted proxy mode (`True`): Inspects `X-Forwarded-For` (validating candidate IPs left-to-right) or `X-Real-IP`, strictly rejecting malformed or script-injected strings using `ipaddress.ip_address` syntax checks before falling back to `request.client.host`.
4. **Actor Metadata**: Populated with `actor_id="fastapi_predict_api"` and `actor_type=AuditActorType.SYSTEM`.

### D. Transaction Timestamp Semantics
Four distinct temporal milestones are explicitly distinguished:
1. **Original Transaction Timestamp (`transaction_timestamp`)**: Extracted from `request.timestamp` or `ctx.transaction_timestamp` (ISO 8601 string or datetime). When provided, timezone-naive datetimes are normalized to UTC.
2. **API Ingestion Fallback**: If `request.timestamp` is omitted by the caller, the database `NOT NULL` constraint on `transactions.transaction_timestamp` is satisfied via an explicit ingestion-time fallback (`datetime.now(timezone.utc)`). Documentation and audit logs explicitly distinguish this as an ingestion-time fallback rather than a client-asserted historical event time.
3. **Risk Evaluation Timestamp (`evaluated_at`)**: Generated upon risk evaluation completion by `RiskService` and persisted directly to `risk_evaluations.evaluated_at` and `audit_logs.event_timestamp`.
4. **Database Record Creation Time (`created_at`)**: Managed independently by database server-default timestamping on every persisted entity table.

### E. Account ID Contract Refinement
- In Phase 8 (stateless ML scoring), `account_id` was optional because isolated gradient boosting inference only evaluates feature vectors.
- For Phase 9 relational persistence, `Transaction.account_id` is an essential `NOT NULL` entity identifier for customer risk profiling and history tracking.
- Omission of `account_id` now triggers a strict `HTTP 422 Unprocessable Entity` validation error. This is documented as an **intentional contract refinement** required for database entity integrity.

### F. Error Handling & HTTP Status Code Conventions
| Condition | HTTP Status | Response Payload | Persistence Action |
| :--- | :--- | :--- | :--- |
| **Valid Request & Evaluation** | `200 OK` | `PredictionResponse` (100% backward compatible) | Atomic commit of all 6 entities |
| **Duplicate `external_transaction_id`** | `409 Conflict` | `{"detail": "Transaction with external_transaction_id '<id>' already exists."}` | Complete rollback; session remains reusable |
| **Missing `account_id` / Mapping Error** | `422 Unprocessable` | `{"detail": "Persistence mapping validation error: <msg>"}` | No database interaction |
| **Database Persistence Failure** | `500 Internal Error` | `{"detail": "Persistence failure storing evaluation result."}` | Automatic rollback via UoW; internal DB details shielded |
| **ML Inference Failure** | `422` or `500` | Standard FastAPI error detail | No database interaction |
| **Upstream HTTPException** | Preserved Status | Unaltered upstream error detail | No database interaction |

### G. API Contract Immutability
The public API response (`PredictionResponse`) remains strictly unchanged. Internal persistence entities, internal UUID primary keys, and foreign keys are never exposed in the response payload.
